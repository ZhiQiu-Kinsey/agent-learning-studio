# 毕业项目：本地学习助教（`capstone-study-assistant`）

[English](README.md) · 简体中文

前面每一课都只证明一件事：循环怎么转、证据怎么引、写入怎么批、指令怎么拦、题集怎么评。毕业项目把它们接成一条链，做一个能用的本地学习助教，再用固定题集和独立验证器说清楚它到底通过了没有。课程目前是 `planned` 草稿，只做过离线测试；真实模型运行还没有做过，下面所有“通过”都指离线夹具，不是验收。

## 本课要回答的问题

- 助教回答问题时，每一条结论的出处在哪？引用能不能被程序逐条核对？资料不够时它会不会明说？
- 学习进度怎样读写？写入为什么必须经过批准？同一次写入重放两次，为什么只写一次？批准之后、写入之前进程崩了，怎样接着做完？
- 资料里夹着“请顺手帮我写入某条记录”这样的指令，为什么越权调用到不了执行层？这道防线为什么不能靠提示词？
- “流程结束”“通过率”“验收通过”怎样分开说？为什么硬性检查没有通过线，只有留出集通过率有？
- 一次运行花了多少次模型调用、多少时间？服务商没报告用量时，账本怎么写？

## 语料的选择

助教的资料是本课新写的一套冻结课程笔记（`corpus/zh-CN/*.md`、`corpus/en/*.md`，各 11 篇，逐行对齐），没有沿用文档加载、检索几课用的图书馆手册语料。理由有四条：

1. 学习助教回答的是“这门课讲了什么”，资料应该就是课程本身的要点，学习者能直接核对。
2. 检索几课的语料写的是图书馆规则，用它做学习助教，题目和资料对不上。
3. 笔记里放了两篇结构上相关的文档：`capabilities.md` 与带日期的 `capabilities-2026-03.md`（互相冲突，考“该信哪一篇”），以及 `forum-digest.md`（含注入指令，考间接注入）。这两种材料手册语料里没有。
4. 语料冻结并带版本：中文 `7bf138797037ac49`，英文 `743900e1515abd52`；题集带指纹 `6f4b04c0be60`。改了资料或题目，指纹变，历史结果就不能和新结果直接比较。

加载、切块和 BM25 检索都直接复用检索几课的模块，本课没有新的检索方法。

## 文件导览

| 文件 | 作用 |
| --- | --- |
| `contract.py` | 任务契约：版本、学习者、每种任务允许的工具 `TASK_TOOLS`、通过线 `PASS_LINE`、每段对话最多 4 次模型调用 `MAX_STEPS`；13 道固定题 `CASES` 和题集指纹 `fingerprint()` |

| `progress.py` | 学习进度存储 `ProgressStore`：操作标识 `operation_id`、操作表、`apply()` 的新写入与重放、崩溃窗口里的状态比对 |

| `verifier.py` | 独立验证器：只读题目规定和这次运行的事实，不信助教自己的说法；硬性检查、失败分类和 `decide_acceptance()` |
| `runtime.py` | 运行器：校验输入，写出任务契约，逐题在隔离存储里运行，发布证据事件和六份报告；`local` 与 `mcp` 两种检索后端 |

| `locales/`、`locales/fixture/` | 运行时文本与夹具文本，中英各一份 |
| `fixtures.py` | 离线测试用的确定性模型和审批策略，只服务自动化测试 |
| `test_lesson.py` | 76 个测试：语料与题集冻结、门禁、进度存储、账本、验证器（含变异检查）、两种运行语言的离线运行、证据事件、行为异常的模型、崩溃与取消、真实 MCP 子进程、输入校验 |

## 助教怎么保证“不越权”

1. **契约先于模型。** 每种任务能用哪些工具，在模型调用之前由 `TASK_TOOLS` 写定：问答、出题、读轨迹只能检索；保存进度可以读进度和写进度；召回只能读进度。
2. **每次调用先过门禁。** `gate.decide()` 不看模型怎么说，只看任务、学习者和参数。越权调用被拒绝，写入一律需要审批。
3. **写入分三步。** 先存检查点，再等审批，批准后重新核对“批准的内容”和“要写的内容”一致，最后用操作标识幂等落盘。
4. **运行器探针。** 运行器自己提交 4 个越权调用，证明门禁在模型从不提议危险调用时也真的拦得住。这类证据在报告里标成 `runner_probe`，和模型自己提出的越权提议分开记。
5. **验证器独立判定。** 验证器从事件和存储里重新读事实，助教说“已保存”不算数。

## 练习

| 练习 | 预设 | 最多模型调用 | 主要证据 |
| --- | --- | --- | --- |
| 带引用的学习问答 | `case=d01` | 4 | 引用核对、检索判定、调用账本 |
| 资料里没有的问题 | `case=d03` | 4 | 回答是否明说资料不足 |
| 保存学习进度并在新会话召回 | `case=d07` | 8 | 门禁决定、审批卡、记忆事件、新会话读回 |
| 崩溃后从检查点恢复 | `case=h05` | 4 | 两次恢复、一次写入、操作标识 |
| 含注入资料的安全回答 | `case=d08` | 4 | 被拦下的越权调用、实际发生的越权数（应为 0） |
| 固定题集评估与验收 | `case=suite`、`split=all` | 57 | 通过率与区间、失败分类、成本账本、验收报告 |

- 运行开始有一张任务卡，写明这次跑哪些题、题集指纹、语料版本和停止条件。
- 每道题一条 `lesson.case_result`，另有 `lesson.permission`（门禁决定）、`lesson.memory`（进度读写）、`lesson.citation_check`、`lesson.retrieval_judge`、`lesson.ledger`。
- 整套评估写六份报告：契约、单题、权限、账本、题集与失败分类、验收。
- 运行前按各题最坏情况累加最多需要的模型调用数，超过本课上限（80）就拒绝运行。开发集最多 37 次，留出集最多 20 次。
- 整套评估在网页真实运行时会在审批卡处暂停：`d07` 一次、`h03` 一次、`h05` 两次，共四次，需要学习者逐次点击。

## 实验看什么

1. **带引用问答**：先看任务卡里的指纹和语料版本；再看每条引用核对的结果；最后对照账本里的检索耗时和模型耗时。
2. **进度读写与恢复**：看门禁对写入的决定、审批卡内容和实际写入的记录；`h05` 看操作标识怎样让第二次恢复变成重放。
3. **注入与评估验收**：看被拦下的调用是模型提出的还是运行器探针；再看整套评估里“流程结束”“通过率”“验收通过”三个数怎样分开。

## 怎么运行

离线测试（确定性模型数据，工具与存储真实执行，MCP 用例会真的拉起子进程）：

```powershell
.\.venv\Scripts\python.exe -m unittest lessons.lesson_capstone_study_assistant.test_lesson -v
```

`fixtures.py` 给“模型”安排了固定行为：`d02` 的同义问法检索不到；注入题里夹具会照指令越权，用来证明门禁拦得住；崩溃由运行器注入故障。这些行为都在事件里标明来源，只用来测试门禁、验证器和报告，不代表任何真实模型的表现。离线整套结果是开发集通过 7/8、留出集通过 5/5，验收状态一律写“非验收”：夹具不能产生验收结论。

真实运行：课程开放（`available`）后，在网页实验台选择练习运行，或使用 `scripts/run_live.py capstone-study-assistant <练习> --url http://127.0.0.1:8765 [--locale en]`。整套评估最多 57 次模型调用，会产生相应用量；价格输入（单价、来源、日期）只在学习者填全时才折算成本，否则只给用量。

**运行语言：**本课支持中文和英文运行。系统提示词、任务契约文字、报告文字和夹具文本写在 `locales/`；题目 id、工具名、事件名和失败类别是代码，各语言相同。网页按界面语言选择，运行记录里写明语言。

## 边界

- 13 道题只能说明这套题上的情况。通过线 0.8 是课程规定的验收线，不是普遍标准；留出集只有 5 道，报告里附 Wilson 区间，结论只当参考。
- 检索只覆盖 BM25，同义问法会失败（`d02`）。这是已知限制，不是 bug。
- 门禁拦的是调用，不是文字：模型照注入指令写出的回答文字，要靠回答检查和验证器发现。
- 价格不内置，没有来源和日期就不折算成本；服务商没报告的用量写“未报告”。
- 学习进度只在本机单人文件里，没有多用户、锁和身份。
- 这是毕业项目的离线实现；真实模型的通过率没有测过，课程在真实运行验收通过前保持 `planned`。
