# 给代码写单元测试的检查清单

## 什么时候用

- 用户给出了函数或类的代码，问“该测什么”“帮我列测试用例”。
- 用户要的是直接能运行的测试代码时，先给清单，再问是否需要代码。

## 做法

1. 先用一句话说明这个函数的职责、输入和输出。
2. 按下面的顺序找用例，每类至少一条：
   - 正常输入：最常见的用法；
   - 边界：空值、0、最大最小值、只有一个元素；
   - 错误输入：类型不对、缺参数、格式不合法，写明期望抛出什么错误或返回什么；
   - 副作用：会不会改动传入的参数、文件或全局状态。
3. 每条用例写清输入和期望结果，期望结果必须能写成一条断言。
4. 不确定期望结果时，把它写成问题留给用户，不替用户决定。

## 输出格式

第一行是职责说明，后面每条用例一行：

- [ ] 输入……，期望……

## 交付前自查

- 至少 5 条检查项，每条以“- [ ]”开头。
- 正常输入、边界、错误输入三类都有。
