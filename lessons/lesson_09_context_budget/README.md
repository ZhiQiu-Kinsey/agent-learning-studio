# Context budget and the truncation window (`context-budget`)

English · [简体中文](README.zh-CN.md)

This lesson has two runs; both need a real model connection, and the `experiment` input decides which one runs.

| Run | Local tool calls | Model requests | What to look at |
| --- | --- | --- | --- |
| `layouts` two layouts | 1 `lookup_lesson` | 2: full history, truncation window | Which messages the window cut to fit `char_budget`, and whether the answer has a source |
| `broken_pair` split a pair | 1 `lookup_lesson` | 2: cut by count, cut by pairs | What the provider does with an orphaned tool message |

`char_budget` is the maximum number of JSON characters the truncation window allows; it is not a token count. `fit_window` first keeps system and the current question, then fills group by group from the newest message back and stops when a group does not fit; a tool message and its assistant call form one group and come in or go out together. When the response has `usage`, it is listed as it is; when it has none, the report says "not reported".

The runner assembles the history: the assistant tool call and the side replies were not generated by the model earlier, and the tool result comes from a real Python read in this run. Material keys are lesson slugs (`messages-context`, `application-state`).

The broken-pair experiment deliberately bypasses the local protocol check of the lesson "Context components and the message protocol" and sends the orphaned tool message as it is. A provider rejection is recorded as `lesson.provider_error` (status, error type, original text, `source`), with no retry and no rewrite. Only a request-level 4xx counts as a rejection (decided by `rejection_status` from "Context components and the message protocol"); timeouts, rate limits, auth failures, connection failures and 5xx are not the provider's verdict on these messages and are raised as errors. In offline tests the 400 is simulated by `fixtures.py` and `source` is `offline_fixture`; to see what a real provider does, run with a real model. `fixtures.py` serves automated tests only.

Rule-based compression, clearing old tool results and model summaries are in the next lesson, "Context compression and probe questions" (`lessons/lesson_context_compaction/`); it imports the character count, the local string check and the helpers that build tool pairs and side discussion from this lesson's `runtime.py`.

**Run language:** this lesson runs in Chinese and in English. The system prompt, the goal, the default follow-up, the layout and truncation names and both reports are in `locales/zh_CN.py` and `locales/en.py`; the parts that the compression lesson uses too (the material, the side discussion, the wording of `answer_text` and `usage_text`, the lookup errors) are in `locales/helpers/`. English text is longer than Chinese, so the same character budget holds fewer messages, but both languages reach the same result: the default budget drops the tool pair as a group.

For references and trade-offs, see `docs/architecture/budget-memory-sources.md`.
