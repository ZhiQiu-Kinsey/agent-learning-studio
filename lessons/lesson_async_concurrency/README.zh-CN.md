# 并行、超时与并发上限（`async-concurrency`）

[English](README.md) · 简体中文

这一课回答一个问题：几件事要同时做，怎样先判断哪些能一起做，怎样不把服务商打满，怎样在慢任务、失败和取消面前不留下半截的、没人认领的活？任务是一份很小的“复习单”：读四份课程笔记（一个有延迟的本地工具），让模型把每份笔记压成一句话，最后汇总成一张复习单。课程用 slug 指代其他课，不用会随课程表变化的课号。其中三个场景需要真实模型连接，`dependency` 场景不调用模型。

## 机制

整套机制分成四个文件，每个文件管一件事：

- **依赖从引用里读出来（`graph.py`）。** 任务的参数里需要别的任务的结果时，写一个 `Ref(任务, 字段)`。`Task` 创建时从参数里找出所有 `Ref`，得到它依赖哪些任务；`levels` 再算层数，同一层的任务互不依赖，才可能同时运行；有环、引用不存在的任务、任务编号重复都直接拒绝。`critical_path_ms` 按测出的耗时算依赖链最长耗时，那是并行的下限。
- **调度器（`scheduler.py`）。** 每个任务是一个 asyncio 任务：先等依赖有结局，再等信号量的名额，拿到名额以后才创建超时，然后把阻塞的工作交给自己开的工作线程。名额要等线程真的结束才放回，已发出的模型请求收不回，也算占着。监视协程每 10 毫秒看一次时钟和停止按钮；停止按钮、整体截止时间和失败策略都走同一个入口 `cancel_all`。每个任务都有一个结局：完成、失败、超时、已取消、跳过，各带原因。
- **本地工具（`tools.py`）。** `read_note` 读一份笔记，等待用停止信号而不是睡眠，所以停止信号一来几毫秒内就返回；等待的时间由调用参数 `delay_ms` 注入，笔记是真的。被锁定的笔记（`lock`）等延迟的一部分就失败。`build_sheet` 汇总复习单，缺输入时返回结构化错误，允许部分时交回自己标明 `complete` 为假的复习单。
- **运行器（`runtime.py`）。** 一次运行把同一张清单按一个场景的几种方式各跑一遍（每遍一个调度器），再写一张对照总表。每遍有自己的 `lesson.graph`、`lesson.task`、可能有 `lesson.stop`，以及一份带检查、指标和任务表的报告。

## 练习

每个练习是一个场景，一次运行里把同一张清单按几种方式各跑一遍，对照在同一次运行、同一份负载下得出：

| 练习 | 场景 | 各遍 | 看什么 |
| --- | --- | --- | --- |
| 依赖图与调度顺序（不调用模型） | `dependency` | 串行、按依赖调度、忽略依赖 | `lesson.graph` 的层；忽略依赖那一遍汇总拿到空值，返回 `MissingInput`；依赖检查指出它在读取结束前就开始了；三遍的墙钟时间 |
| 并发上限 1、2、4 | `limits` | 上限 1、2、4 | 峰值并发由时间戳重新算出，等于上限；模型调用数每遍 4 次；墙钟时间约 4 : 2 : 1；请求的 `branch` 带对照组的名字 |
| 超时与整体截止时间 | `timeouts` | 慢但不设超时、单任务超时、整体截止时间 | `TaskStopped`；依赖超时任务的摘要被跳过（`blocked_by`）；复习单自己标明不完整；`lesson.stop`；放弃等待之后才停下的任务（`late_ms`） |
| 失败后继续或全部取消 | `failure` | 失败后继续、失败后全部取消 | `NoteLocked`；继续是 3 次模型调用，全部取消是 0 次；`lesson.stop` 记下触发者和当时在跑的任务 |

学习者点停止和断开事件连接这两件事要手动触发，步骤写在实验台的“手动核对”里：停止之后平台不再收课程事件，所以证据是没有 `tool_result` 的 `tool_call` 和 `done` 事件的 `cancel_reason`。

## 文件

| 文件 | 内容 |
| --- | --- |
| `graph.py` | `Ref`、`Task`、依赖层数、依赖链最长耗时 |
| `scheduler.py` | asyncio 调度器：依赖、并发上限、单任务超时、整体截止时间、失败策略、取消、线程登记 |
| `tools.py` | `read_note`（可注入延迟、可锁定、听停止信号）和 `build_sheet`（缺输入报错或标明不完整） |
| `runtime.py` | 自定义运行器：场景与对照组、任务清单、事件、每遍报告和对照总表 |
| `locales/` | 中英文运行时文本：笔记、提示词、任务和报告文字；`locales/fixture/` 是离线夹具的摘要文字 |
| `fixtures.py` | 只服务自动化测试的确定性回答；网页没有入口 |
| `content.json`、`content.en.json`、`lesson.json`、`lesson.en.json` | 教学内容和实现清单，及英文译文层 |

## 运行

离线测试（夹具给出确定性的摘要，工具、线程、超时和取消都是真实执行的；用的是很短的真实延迟，没有虚拟时钟）：

```powershell
.\.venv\Scripts\python.exe -m unittest lessons.lesson_async_concurrency.test_lesson -v
```

真实运行需要先配置模型（环境变量或 `local_config.py`），再启动服务：

```powershell
.\.venv\Scripts\python.exe run_web.py
.\.venv\Scripts\python.exe scripts/run_live.py async-concurrency concurrency-limit --url http://127.0.0.1:8765 [--locale en]
```

真实运行会产生模型用量：并发上限场景一次发 12 个摘要请求，超时场景最多 11 个，失败场景 3 个。本课目前仍是规划草稿：只做过离线验证，没有用真实模型运行过。

## 能证明与不能证明

- 时间是后端单调时钟量出来的，但延迟是注入的：真实慢工具和真实服务商的耗时有波动，倍数不是通用的。
- 峰值并发由时间戳重新算出，能发现名额放回得太早；它不能证明服务商那边同时在处理几个请求，那一端我们看不到。
- 取消只停止等待和后续动作：工具听得到停止信号，几毫秒内就停；已发出的模型请求收不回，线程只能等响应，服务商照样生成和计量。
- “忽略依赖”是故意做的错误调度，只出现在 `dependency` 场景。真实系统里缺输入的错误不一定被工具拒绝，有的会悄悄用旧值。
- 并发上限不能代替依赖：有限的名额只是改变先后，不保证依赖的结果已经存在（见 `test_lesson.py` 里的对照）。
