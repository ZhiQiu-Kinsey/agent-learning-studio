# Real-model verification of the 29 planned lessons, 2026-10-21

**English** · Every exercise of the planned lessons was run once in each runtime language against a real model. This file records what was run and what was found; it is a dated record, not a guarantee for other models. No lesson status was changed: the recommendations at the end are suggestions, the maintainer decides.

## Setup

| Item | Value |
| --- | --- |
| Provider / path | Anthropic through LiteLLM (`sdk_standardized`) |
| Model | `claude-haiku-5-5` |
| Date | 2026-10-21 |
| Lessons | 29 planned lessons, every exercise, zh-CN and en |
| Tool | a local driver around `scripts/run_live.py` (same API calls, saves each run's events under `.runtime/live/`, answers approvals by a fixed policy) against a local backend on port 8790 |
| How planned lessons were run | a local wrapper that loads the lesson list with `load_lessons(include_planned=True)`; nothing was changed in `curriculum/catalog.json` and no switch was committed |

The first attempt used `claude-sonnet-5-5`. Both it and `claude-haiku-5-5` answer a request that carries `temperature` with HTTP 400 (`temperature is deprecated for this model`), which stopped the first real call of most lessons. With the maintainer's decision, the platform now leaves a parameter the provider rejects for the model out of the request and says so (`request.data.omitted_params`; see `docs/architecture/event-envelope-v2.md`), and the runs below used `claude-haiku-5-5`. In every request of these runs `temperature` is therefore absent from `body` and listed under `omitted_params` (`{"temperature": 0}` and the like). Lessons whose text talks about `temperature 0` were judged with that in mind.

### Approvals

My driver answered every approval card by a fixed policy, so some approval outcomes are mine, not the lesson's design:

- default: approve; for commands (`bash-coding-agent`, `file-edit-evidence`) approve only if the command starts with `python`, `ls`, `cat`, `head`, `tail`, `sed`, `grep`, `wc`, `find .`, `echo`, `pwd`, `diff` (or a cache `rm`) and contains no network, path-escape or secret pattern; reject otherwise. This also rejected the model's opening compound command (`cd . && ls -R …`) in every `bash-coding-agent` run and some `find` listings, which the lesson's text does not expect.
- `hooks-approval` `reject-timeout`: reject the first card, leave the second unanswered (timeout). `edit-recheck`: approved with the recipient edited to `carol@outside.example`. `human-in-the-loop` `edit-state`: approved with difficulty `hard` and the title suffixed. `capstone-study-assistant` `evaluate`: approve, reject (`h03`), approve, approve.
- `human-in-the-loop` `restart-resume` and `crash-after-write`: the backend was stopped and started again, then the run was resumed from the `approved` checkpoint through the resume endpoint.
- Commands approved in `bash-coding-agent` ran on this machine in a throwaway workspace by the restricted runner, which is not isolated; 49 commands were approved in `bash-coding-agent` and `file-edit-evidence`; I searched their first 200 characters afterwards for network, path-escape, `rm` and secret patterns and found none (long `python -c` snippets were not read in full).

## Observation points

Each observation point of each experiment was checked with `server/selectors.py` `select_events` over the events of every arm. 1,025 of 1,050 point checks hit (zh-CN 516 of 525, en 509 of 525). The 25 that did not, and why:

| Lesson / experiment / point | Language | Why it did not hit |
| --- | --- | --- |
| rag-citations `triage-failures` / `unprovided` | both | the model cited only provided chunks; the "cited an unprovided chunk" error exists only in the offline fixture |
| agentic-rag `no-answer` / `repeat`, `repeat-note` | both | the model never repeated a search term |
| hooks-approval `write-approval` / `rewrite-on-read` | both | the model wrote the ticket number in capitals itself, so `normalize_arguments` rewrote nothing |
| hooks-approval `edit-recheck` (4 points), `swap-guard` (2 points) | en | no approval card: the model read the ticket, saw it was not "done" and asked the user instead of proposing the notice (zh did propose it) |
| bash-coding-agent `timeout-and-truncation` / `timeout`, `omitted`, `process-tree` | both | in the repeated runs the model piped the script into `| tail` or stopped it with its own `timeout`, so the platform timeout and truncation never showed (the first runs: `omitted` missed in zh only) |
| evaluation-sets `version-compare` / `violation` | both | no case had a process violation in either version |
| prompt-injection `defense-compare` / `fixture-mark` | both | the mark exists only in offline fixture runs (expected) |
| capstone-study-assistant `cited-answers` / `declined` | en | `d03` failed on answer format before the check could run (the `missing` field was over 300 characters); in zh the model kept searching and the run ended `not_ended`, and the repeated zh run answered |

Points that miss only in arms they do not belong to are not listed.

Not an observation-point miss but worth saying: in `prompt-injection` the real model **never proposed an out-of-scope call** in any exercise or language (`attack`, `compare` in all three arms, `propagation`). Every refused call in those runs is a runner probe (`source: program`), and the reports say "only runner probes (the model proposed nothing out of scope this time)" and "not tested" for the three defense checks. These runs therefore say nothing about whether the defenses hold against a persuaded model.

## Text corrected after the runs

Each lesson was audited against its real events by reading its guide steps, hypotheses, conclusions, predictions, check questions and README, in both languages; the changes below are in `content.json` and its English layer, one commit per lesson.

- **document-loading**: the trust experiment's hypothesis no longer implies the model follows the comment when material is mixed in; neither real run did, and a reply that quotes the comment to refuse it also fails the keyword check.
- **keyword-retrieval**: "cross-section queries need a second chunk" is now "most" (in English `q10` fits in one chunk).
- **rag-citations**: the triage guide, the section text and the "find the unprovided chunk" task say the two errors come from the offline fixture and that a real model may not make them; a too-long `missing` is described as a malformed answer that hides a retrieval miss.
- **agentic-rag**: the multi-hop hypothesis and guide no longer promise that the loop fills the second hop (zh did in 2 searches; en used 4 searches and still missed it); the no-answer text no longer promises an empty first search or a repeated search term; the one-search quiz now says the model may propose the second search in the same response and the runner refuses it.
- **langchain-vs-native**: the request difference is not "re-serialized `arguments`" (identical in all four runs); it is the generated tool definition, `tool_choice`, floats, and provider fields dropped on write-back.
- **langchain-tools**: only the missing-field arm behaves as written; the wrong-fact arm was not stopped by the business check in either language (zh ignored the injection, en failed the schema on a too-long field first), and `normal` also needed a repair in en.
- **streaming-cancel**: "first token much earlier, totals similar" holds for zh and not for en (the model reasoned first: first token at 79% of the total, streamed run slower than the plain run); "the first chunk usually has no text" is the opposite in zh; the partial-continue hypothesis holds in en only.
- **async-concurrency**: ignoring dependencies is "about as fast" (zh: 231 vs 210 ms), the critical path differs per variant because model latency is part of it, and "no timeout is much slower" failed in en (2567 vs 2605 ms).
- **hooks-approval**: no run called `list_records`; "reject then timeout" did not involve a broadcast notice in any run (the first card was the status update); three runs had no card at all because the model asked instead of proposing (see above).
- **bash-coding-agent**: failing tests can return `exit_code` 0 when the model pipes the run into `| tail`; the tamper arm never edited the tests, so the "tests green but not accepted" case is now stated as conditional; no delete command reached an approval card; truncation depends on how the model runs the script.
- **file-edit-evidence**: line numbers expire after any write (not only one that changes the line count); refusals happened only in the `lines` arm; "far fewer characters" for line replace is now "fewer".
- **evaluation-sets**: `temperature 0` was asked for but omitted by the platform; the real improvement was the tool-failure case (version A answered NONE without calling a tool); `given-distance` called the tool in both versions, so it is not a regression caused by the new rule; judge calibration had no disagreement to read.
- **prompt-injection**: all "refused proposal" wording now says the refused call may be a runner probe, and the comparison guide, conclusions, quiz and prediction no longer assume the model was persuaded.
- **mcp-lifecycle**: in the model arm the write was confirmed before the process was killed and the disconnect hit a read; the arm ended on the 4-round limit after one retried read; the "no real-model run" sentence is replaced by what the two runs showed.
- **multi-agent-patterns**: input characters rise with the split but not strictly (roles > multi); the independent-agents arm was the slowest in wall-clock time in both languages; single and multi each failed a topic in some runs.
- **delegation-budget**: "5 of 5 pass" and "the late policy is delivered" depend on the model keeping `value` under 40 characters; in en it did not.
- **long-running-tasks**: after the first failure the model did not retry until the goal check handed "still to start" back; the budget exercise was stopped by a 40 s default deadline (exit 124) before the model restarted the scan, with no polling and no cancel by the model.
- **goal-loops**: with this model, the 2-round arm and the hasty worker both finished in one round, so neither budget exhaustion nor a claim/verdict disagreement showed; the text is now conditional.
- **local-delivery**: the "nothing configured" scenario also sets a malformed port.
- **backup-upgrade**: the `damage_caught` item passes in both restore arms; the difference is whether it was found before or after the restore. The memory copy of `VACUUM INTO` has 20 rows, not 14.
- **capstone-study-assistant**: the no-answer case does not always return noise chunks and in these runs did not reach the `declined` check; "find the out-of-scope proposal the model made" now says the refused write is a runner probe because the model proposed none; the injected chunk reached the request in zh and not in en.
- **reliable-tools, observability-cost, human-in-the-loop, a2a-delegation, mcp-basics, langgraph-state, hybrid/embedding (not run)**: no claim contradicted in the real runs (reliable-tools and observability-cost needed only wording fixes in the English runtime text below).

## Runtime fixes made because of the runs

- `course/execution.py`, `course/providers.py`, `server/app.py`: omit parameters the provider rejects for the model and record them in `request.data.omitted_params` (tests in `tests/test_execution.py`, `tests/test_providers.py`).
- `course/sandbox.py`: the command policy no longer treats a bare `/` after `:` as an absolute path. `sed -i 's/ … > 90:/ … >= 90:/'` was denied as `absolute_path` in 7 of the first 8 `bash-coding-agent` runs and sent the model into extra rounds; the repeated runs approved it (test in `tests/test_sandbox.py`).
- `lessons/lesson_capstone_study_assistant/verifier.py`: only a version-conflict case is judged on disclosing a conflict. `h02` had failed in both languages because two versions had been retrieved as noise (test added).
- Prompts of `rag-citations` and `capstone-study-assistant`: state that `missing` is at most 300 characters; a correct "material insufficient" answer had been scored as a malformed answer.
- `backup-upgrade`: the `damage_caught` label no longer says "before anyone used it".
- English runtime text: plurals and a duplicated phrase (`1 writes`, `1 were running`, `1 times`, `1 rounds`, `1 leaks`, `Ended as ended normally`, and the like) in `async-concurrency`, `file-edit-evidence`, `observability-cost`, `reliable-tools`, `long-running-tasks`, `goal-loops`, `local-delivery`, `streaming-cancel`.

### Runs repeated after fixes

After the fixes above the affected exercises were run again once per language and the later run replaces the earlier one in the counts: `rag-citations` `triage`, `capstone-study-assistant` `no-answer` and `evaluate`, and `bash-coding-agent` `fix-test`, `tamper`, `slow-check` (12 runs). Results: `triage` completed with the answer format accepted in both languages; `no-answer` zh now answered and passed the `declined` check, while en again failed the answer format although the prompt now states the 300-character limit (so the prompt line does not guarantee the model keeps to it); `evaluate` went from 9 of 13 in both languages to 11 of 13 in zh (interval 58%–96%) and 10 of 13 plus 1 unassessable in en (interval 50%–92%); and `sed` was approved in every repeated `bash-coding-agent` run. The pass-rate difference between the first and the repeated run is the spread of one model on one suite, not an effect of the fixes. A repeat is a second sample, not a confirmation.

### Found and not fixed

These are open for the maintainer; they are described in the audit findings, not changed here.

- `agentic-rag`: in zh runs, tool-call `arguments` are stored as `\uXXXX` escapes in learner-visible events (the readable query is in `lesson.attempt`).
- `human-in-the-loop`: the English topic "Filter the even numbers out of a list" is ambiguous ("filter out" can mean remove), and the drafts contradicted their own titles in every English run; checkpoint ids restart at `cp-1` in a resumed run on the same thread.
- `capstone-study-assistant`: the answer text for a run that never answered reads "answer was malformed" (`not_ended`); the permission detail says "0 executions" in `h05` although a write ran after resume; the English failure table lists an unassessable case as a failure class.
- `hooks-approval`: the task texts say a ticket "is done" while the seeded ticket is open, which makes a careful model ask instead of acting; the recheck denial does not name the edited field.
- Several READMEs still say "planned, verified offline only, no real-model run"; they were not edited because the status is the maintainer's call.

## Not verified

- `embedding-retrieval` and `hybrid-retrieval`: Embedding part not verified (no Embedding provider configured; Anthropic has no Embedding interface and none was added). The platform refused all 16 runs at creation and said so; the exercises that need no embedding were not separated out, so none of the two lessons' text was checked against a run. The local parts are covered by their offline tests only.
- `prompt-injection`: the defenses were not tested against a persuaded model (see above).
- `streaming-cancel`: the saved `long-stream` runs are the "do nothing" case; the stop and disconnect arms of that experiment are not in the saved runs.
- Running the lesson on the web page: only the API path was exercised; the web pages were not opened.
