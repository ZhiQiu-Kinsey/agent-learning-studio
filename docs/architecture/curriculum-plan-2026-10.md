## 2. 现有课程扩展

| 课 | 新增练习 | 运行证据 | 离线测试怎么做 |
| --- | --- | --- | --- |
| 4 任务目标与验收 | `self-report`：执行者自报“已完成，答案 42”，但没有工具证据；`goal-loop`：第 1 次尝试注入错误，验收器给出原因，第 2 次修正；`goal-loop-once`：同样的循环但只允许 1 次 | `lesson.completion_claim`（声称）、`lesson.goal_check`（每次尝试的验收结论与原因）、报告中的停止原因 | 本课不调用模型，全部是本地 Python，测试直接断言事件 |
| 6 提示词与工具描述 | `tool-matrix`：同一工具的描述写成空白 / 良好 / 误导三种，各配两道题（该调用、不该调用），共 6 次模型请求 | 每格的 `tool_calls` 提议；提议被执行时记录真实 `tool_result`，看误导描述把模型引向哪里 | fixture 按“描述 × 题目”返回确定性提议，Python 工具真实执行 |
| 9 上下文预算与压缩 | `compaction`：不压缩 / 清理旧工具结果 / 模型摘要三组，用探针问题检查最早那次工具结果是否还能答出；`broken-pair`：按条数截断时把 assistant 工具调用切掉，只剩孤立的 tool 消息，原样发给服务商 | 摘要请求与三次探针请求；服务商拒绝时记录 `lesson.provider_error`（状态码、错误类型、服务商返回的说明） | 400 只能用 fixture 模拟，事件里标注 `source: offline_fixture`；真实 400 需要用户用真实模型运行后查看或录制 |
| 10 持久记忆 | `scope-filter`：同一命名空间里有 persistent、上一任务的 current_task、本任务的 current_task 三类记录，召回时按范围过滤，任务结束后清理 current_task；其中一条记忆写着“忽略之前的规则……” | `lesson.memory` 的召回、过滤、清理事件；召回结果被包成“数据块”的消息（只构造、不发送） | 一次性临时库，与 live 模式相同 |

第 10 课仍不调用模型。召回的“指令”是否会被真实模型执行，留到提示注入课（`prompt-injection`）用真实模型检验；本课只展示程序这一侧的处理：不放进 system、按数据转义、记录疑似指令的启发式标记。

每课共同要求：

- 不调用模型的部分（解析、验收、路由统计）写成纯函数，有单元测试。
- 需要模型的部分用 fixture 做离线测试，fixture 只用于测试，不出现在学生网页。
- `content.json` 至少一个实验，实验覆盖全部练习；观察点选择器在确定性运行中命中；结论写清“能证明 / 不能证明”。
- 术语首次出现按 `curriculum/glossary.json` 写“中文（English）”；缺的术语先补进术语表。
- 离线验收（全部测试与校验通过）后把状态改为 available，并在最终报告里单列“尚未用真实模型验证”。

## 4. 正文修订的标准

用户要求降低“AI 味”。修订时遵守：

- 一句话只说一件事，删掉“值得注意的是”“需要强调”“本质上”之类的铺垫。
- 概念卡的 description 不重复标题；walkthrough 每步不重复“示意不代替本次运行记录”，统一由块的标注说明。
- 少用排比和“不是……而是……”句式；能用具体数字或字段名就不用形容词。
- 不改事实字段（id、正确答案、代码、选择器、路径）；改正文后跑 `migrate_content.py --check` 与全部测试。

## 8. 第二轮：节奏、读码与课程表细化（2026-10-03）

### 8.1 审计结论（2026-10-02，16 门可运行课）

| 问题 | 结论 | 依据 |
| --- | --- | --- |
| 课程表细度 | 不够 | 每课都是同一模板（3 目标、若干关键词、1 个实验、3 条验收），没有小节、时长、难度、是否调用模型；第 4、10、18 课的实验与验收和实现不一致 |
| 节奏 | 起点陡、密度高，不是篇幅长 | 理解正文均 640 字却带 21 个代码名；第 1、9、10 课各 9–11 个新概念；第 1 课前没讲过一次模型请求、角色、system、temperature |
| 读码复杂度 | 偏高 | 约 20% 展示行是平台代码；第 1 课读的是生产版 `run_agent`，循环块 49% 是事件、打印、取消、计时 |
| 批注 | 偏少 | 平均 10.3 行一条，41 段里 27 段有超过 12 行的空段；第 5 课 `execution.py` 的 3 条批注整体错位 5 行 |

参考：Hello-Agents（4b014ad，CC BY-NC-SA 4.0，只借鉴思路，不搬原文和代码）。借鉴“每个范式固定讲法”“代码按职责分块并标位置”“自检分四级（判断 → 消融 → 小扩展 → 开放设计）”；不借鉴文本协议作主线、框架包黑盒、删改或模拟的运行日志、关键词终止反思、过长的理论铺垫。

### 8.2 决定（用户 2026-10-02 确认）

1. **新增 0 单元“模型调用基础”**，放在“原生基础”最前面的模块 A0，共 3 课：一次模型请求、多轮对话靠程序重发历史、采样与不确定性。全部用真实运行，每课新概念不超过 4 个。
2. **拆分超载课**：
   - 第 1 课 → ★`tool-proposals`（工具定义与调用提议，只看提议、不执行）+ `tool-selection`（执行工具与回传结果；slug 不变，现有实现与测试都依赖它）；“同一轮多个调用”移到 `dependent-calls`。
   - 第 9 课 → `context-budget`（预算、截取窗口、拆开配对）+ `context-compaction`（规则压缩、清理旧结果、模型摘要与探针）。
   - 第 10 课 → `persistent-memory`（保存、重开、命名空间与召回）+ `memory-lifecycle`（版本冲突、过期删除、召回范围、召回内容只当数据）。
   - 规划课中的捆绑主题一并拆开（见 8.5）。
3. **读码改法**：重构运行器，让真实运行的循环本身就是教学版；剩余平台代码可折叠；批注设门槛并带锚点校验；行内注释用中文写“为什么”，按步骤编号。
4. **执行方**：本会话实现。用户指定顺序：
   1. 决定写进文档；
   2. 同步术语改动；
   3. 修第 5 课错位批注、旧课号别名冲突、principles 里过期的课号；
   4. 读码重构；
   5. 0 单元与拆课。

   目标是完成“上下文与状态”（第三章）的全部课程。用户 2026-10-03 允许调用真实模型做验证。

### 8.3 节奏规则（`validate_lessons` 检查能检查的部分）

- 一课只学一件事；本课引入的课程概念（术语表 `first_lesson` 指向本课的条目）不超过 5 个。
- 一段正文最多引入两个新概念（术语规范第 3 节已有）。
- 实验不超过 3 个；理解场景在第一道微测之前就给出“先跑一次”的入口。
- 不调用模型的课在课程表和课程页标明“本课不调用模型”。

### 8.4 读码规则

| 规则 | 检查方式 |
| --- | --- |
| 每条批注带 `anchor`：该行必须包含的一段原文 | `validate_lessons`；源码移动后批注错位会直接报错 |
| 批注密度：展示范围内每 8 个非空、未折叠行至少 1 条；连续无批注不超过 12 行 | `validate_lessons`；已有课的超标块记在基线里，基线只许减少 |
| 平台代码用 `folds: [{start, end, label}]` 折叠成一行灰字，可一键展开 | 写在 content.json，不改源码，不影响录制的源码哈希 |
| 读码页默认只显示标注范围，范围外的行收起为“展开其余 N 行” | 前端 |
| “本课新增”只统计 `lessons/` 下的课程文件，不含测试夹具和平台文件 | 后端 |
| 源码清单的每个文件标角色：课程代码、平台、测试夹具 | `lesson.json` 的 `sources[].role` |
| 行内注释写“为什么”，中文；循环按步骤编号（`# 1.`、`# 2.`） | 作者自查 |

运行器重构的目标：`run_agent` 只剩消息历史、请求、判断结束、执行与回传四步，事件、计时、取消和深拷贝由 `RunContext.complete` 与工具执行器在边界上完成。

### 8.6 课号别名

规划课的数字别名来自重排前的旧编号，从未能打开，却和现在的显示课号撞号（例如别名 `11` 指向资料加载，显示的第 11 课是提示缓存）；插入 0 单元后，可运行课的数字别名也会和显示课号错开。决定：删除全部数字别名，测试和文档改用 slug；`aliases` 机制保留，只用于将来 slug 改名。

### 8.7 课程表细化

catalog 每课增加：`estimated_minutes`（预计时长）、`difficulty`（入门 / 进阶 / 挑战）、`sections`（小节标题与一句话要点）。可运行课的小节由 content.json 的正文节标题导出并校验一致，“是否调用模型”从 lesson.json 读取；规划课由作者填写。课程列表与路线图详情显示这些字段。
