## 学习原则

- 本文件是课程分类、课号、先修和规划状态的唯一主数据；网页、API 与课程文档从同一份数据生成。
- 课程以稳定的 slug 标识，旧数字编号只作别名；显示课号按目录登记顺序计算，插入新课无需改 ID。available 表示平台已有实验，不表示学习者已经掌握。planned 课程仅展示计划，尚不能运行。
- 每课按目标、原理、读代码、预测、实验、trace 对照与自检推进；下列规划实验是后续制作要求，登记课程不等于完成教材和代码。
- 先修按知识依赖设置；RAG 不必先学持久记忆，LangChain 不必先完成 Agentic RAG，独立评估可以在任务验收课后开始。
- 从第 8 课建立最小验收案例，各阶段继续保留成功和边界案例，第 40 课再集中研究独立验证、留出集与回归。
- 采用服务商无关的统一模型接口，百炼作为当前已实测配置；通过成熟 SDK 或适配层支持其他服务，分别保留原始 HTTP 与适配层输入输出。控制变量实验固定当次模型与配置，不限定长期服务商。新增框架按课安装可选依赖，正式实现时核对官方文档并锁定版本。
- 从资料加载课开始说明外部文本不可信，完整权限和提示注入实验在第 43 课完成；程序决定工具执行范围，提示词不能替代权限控制。
- 每个阶段为同一个本地学习助教增加能力，同时保留可独立运行的小实验；阶段成果以引用、参数、状态、实际副作用和终态验收。
- 课程实验以真实模型和真实工具为主；模拟仅供内部自动化测试，不作为学习主线。回放不重新执行工具或模型；模型输出、工具结果、状态更新分别记录，服务商实测、估算和未知指标明确区分，不把动画当作模型内部思考。
- 参考项目提供结构和工程思路，本课程描述与实验原创编写；阅读、源码存在、历史测试和本机复现分别说明，引用固定快照，不宣称整套教程已实现。

## A · 原生基础

从一次模型请求出发，到真实的 Python 工具调用，看懂模型决策、执行结果和失败边界。

### A0 · 模型调用基础

一次请求、多轮历史与采样波动：后面每一课都建立在这三件事上。

#### 第 1 课 · 一次模型请求

**课程 ID：** `chat-request`

**层级：** 必修　**状态：** 规划中

**先修：** Python 函数、字典、异常与 JSON 基础

发出一次不带工具的真实模型请求，读懂请求体里的 model 与 messages、响应里的回答、结束原因和用量。

**学习目标**

- 说出一次模型请求由哪些字段组成
- 从响应中找到回答、结束原因与用量
- 解释系统提示词和输出长度上限如何改变一次回答

**知识点与分节**

- 请求体：model 与 messages
- 消息角色：system、user、assistant
- 响应：choices[0].message.content
- 结束原因 finish_reason：stop 与 length
- 用量 usage 与 Token
- 密钥只在后端

**实验计划**

同一问题：有无系统提示词、限制输出长度：

1. 先预测去掉系统提示词、把输出上限设得很小时，回答和结束原因会怎样变化。
2. 分别运行三个练习，展开请求体与响应，标出 messages、content、finish_reason 和 usage。
3. 比较三次的提示 Token 与回答长度，说明哪些差异来自请求本身。

产出：三次真实请求的字段标注与对照说明。

**验收要求**

- 能指出请求体里的 model、messages 和每条消息的角色。
- 能从响应读出回答、结束原因和服务商报告的用量；没有报告的用量写“未报告”。
- 能解释输出被截断时 finish_reason 为什么是 length。

**参考材料**

- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/messages-and-special-tokens.mdx`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。

#### 第 2 课 · 多轮对话：程序重发历史

**课程 ID：** `multi-turn-history`

**层级：** 必修　**状态：** 规划中

**先修：** 第 1 课 一次模型请求

连续提问两次，比较带上与不带上一轮消息的请求，看清模型不会自己记住上一轮，多轮对话靠程序重发消息历史。

**学习目标**

- 解释模型调用之间不保存状态
- 按轮把 assistant 回复放回消息历史
- 从用量看出历史越长、每次请求越大

**知识点与分节**

- 一次调用不保存状态
- 消息历史与 assistant 回复回填
- 带历史与不带历史的对照
- 提示 Token 随轮次增长
- 上下文就是这一次请求里的全部内容

**实验计划**

第二个问题：带历史与不带历史：

1. 先预测只发第二个问题时，模型能否回答依赖第一轮的内容。
2. 运行带历史与不带历史两个练习，对照两次请求的 messages。
3. 运行三轮对话，记录每轮的提示 Token。

产出：两种请求的消息对照与三轮用量变化。

**验收要求**

- 能指出第二次请求里哪几条消息来自上一轮。
- 能解释不带历史时模型为什么无法回答。
- 能从用量记录说明历史增长带来的成本。

**参考材料**

- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/messages-and-special-tokens.mdx`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`chapter1/context/agent.py`。

#### 第 3 课 · 采样与不确定性

**课程 ID：** `sampling-variance`

**层级：** 必修　**状态：** 规划中

**先修：** 第 1 课 一次模型请求

同一提示连续运行多次，比较低温与高温下回答的差异，理解为什么一次运行不能证明结论、实验要重复。

**学习目标**

- 解释模型输出来自采样
- 比较采样温度对回答波动的影响
- 说明对照实验为什么要固定条件并重复运行

**知识点与分节**

- 采样与概率分布
- 采样温度 temperature
- 温度为 0 也不保证完全相同
- 重复运行与不同回答数
- 一次运行能证明什么、不能证明什么

**实验计划**

同一提示：低温与高温各运行 5 次：

1. 先预测温度为 0 与较高温度时，5 次回答会有几种不同说法。
2. 分别运行两个练习，每次连续发出 5 个相同请求。
3. 比较不同回答数与用量，说明后面的对照实验为什么要多跑几次。

产出：两组各 5 次真实回答的对照表。

**验收要求**

- 每个回答都来自真实响应，不同回答数由程序统计。
- 能说明温度只改变采样方式，不改变请求里的信息。
- 能指出一次运行的差异可能只是波动。

**参考材料**

- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。
- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/what-are-llms.mdx`。

### A1 · 工具调用

从调用提议到执行回传，再到工具之间的数据依赖。

#### 第 4 课 · 工具定义与调用提议

**课程 ID：** `tool-selection`

**层级：** 必修　**状态：** 已可运行

**先修：** 第 1 课 一次模型请求

把工具定义随请求发给模型，只看模型提出的调用：选哪个工具、参数是什么，本课不执行任何工具。

**学习目标**

- 读懂工具定义里的名称、描述和参数 JSON Schema
- 从响应找到 tool_calls 与 JSON 字符串形式的参数
- 区分“模型提出调用”和“程序执行工具”

**知识点与分节**

- tools 与 JSON Schema
- 工具描述决定何时被选中
- tool_calls 与 arguments
- finish_reason 为 tool_calls
- 不需要工具时直接回答
- 调用提议不等于执行

**实验计划**

加法、查时间与闲聊：模型提出什么：

1. 先预测三个问题各会不会提出调用、提出哪个工具。
2. 分别运行三个练习，展开响应里的 tool_calls 和 arguments。
3. 确认事件里没有工具结果：本课只观察提议。

产出：三条调用提议的标注记录。

**验收要求**

- 能从响应找到工具名和 JSON 字符串参数。
- 能解释闲聊问题为什么没有调用提议。
- 能指出本课运行里没有任何工具被执行。

**参考材料**

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。

#### 第 5 课 · 执行工具与回传结果

**课程 ID：** `tool-results`

**层级：** 必修　**状态：** 规划中

**先修：** 第 4 课 工具定义与调用提议、第 2 课 多轮对话：程序重发历史

让 Python 按白名单执行模型提出的调用，把工具结果用同一个调用 id 写回消息历史，再请求一次模型，形成最小 Agent 循环。

**学习目标**

- 说明运行器如何按名字分派到登记的函数
- 用 tool_call_id 把调用和工具结果配对
- 追踪工具结果如何进入下一次请求并成为回答依据

**知识点与分节**

- 登记的工具与分派
- role=tool 消息与 tool_call_id
- 第二次请求里的工具结果
- 最小 Agent 循环的四步
- 轮数上限
- 回放只读取已有记录

**实验计划**

加法与查时间：完整的一次循环：

1. 先预测一次加法会产生几次模型请求、几个工具结果。
2. 运行练习，按顺序标出调用提议、工具结果和第二次请求。
3. 在第二次请求的 messages 里找到工具结果，说明回答的依据。

产出：一次完整循环的事件标注与调用 id 连线。

**验收要求**

- 能用同一个 tool_call_id 对应调用与工具结果。
- 能指出第二次请求比第一次多了哪两条消息。
- 能解释工具由 Python 执行，回放没有再次调用模型或工具。

**参考材料**

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。

#### 第 6 课 · 依赖式多轮调用

**层级：** 必修　**状态：** 已可运行

**先修：** 第 5 课 执行工具与回传结果

读取本次真实时间，把上一步的 hour 和 minute 作为下一步加法参数；再对照同一轮提出的两个独立调用。

**学习目标**

**知识点与分节**

- 依赖图与独立任务

- 下一轮参数构造

### A2 · 错误与执行边界

通过失败案例确认校验、白名单和停止条件的责任。

#### 第 7 课 · 错误处理与安全边界

**课程 ID：** `fail-safely`

**层级：** 必修　**状态：** 已可运行

**先修：** 第 6 课 依赖式多轮调用

通过真实正常除法、零除和越界请求观察模型及工具行为，再以独立程序校验确认未知工具和损坏参数无法绕过边界。

**学习目标**

- 把执行错误作为结构化结果回传
- 确认只执行明确登记的工具
- 区分运行结束、任务成功和预算耗尽

**知识点与分节**

- 参数 JSON 解析与输入校验
- 工具白名单
- 工具异常与 ok=false 的工具结果
- 模型收到错误后的行为
- 轮数预算与停止条件
- 真实模型行为与独立程序校验

**实验计划**

失败安全对照：

1. 通过真实模型运行正常除法与零除，预测并检查各自的工具结果和最终回答。
2. 请求一个未提供的运算或越界操作，观察模型是否调用工具、说明限制或给出无依据回答；未触发的行为如实记录。
3. 阅读并直接验证程序的白名单与参数校验，分别记录未知工具和坏 JSON 的确定性拒绝，与真实模型运行证据区分。

产出：真实模型正常/失败记录、独立程序边界验证及约束责任表。

**验收要求**

- 未知工具未被执行，损坏参数没有绕过解析和校验。
- 零除以错误结果呈现，最终回答没有把失败结果当作有效数字。
- 能指出终止原因，并解释到达轮数上限不能等同任务完成。

**参考材料**

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。

## B · 任务与接口

### B1 · 任务定义与结果契约

定义成功标准，区分结构合法和业务正确。

#### 第 8 课 · 任务目标与验收

**课程 ID：** `task-contract`

**层级：** 必修　**状态：** 已可运行

**先修：** 第 7 课 错误处理与安全边界

在继续写 Agent 前，明确输入范围、输出、约束、证据、失败处理与停止条件，建立最小验收基线。

**学习目标**

- 把模糊需求写成可检查任务卡
- 为正常和边界输入定义成功标准
- 区分生成回答、执行结束与业务完成

**知识点与分节**

- 用户目标与可执行任务
- 输入输出与数据范围
- 成功和失败判据
- 证据要求与未知处理
- 依赖关系与停止条件
- 固定案例与独立检查
- 声称完成与证明完成
- 有上限的目标循环（预告）

**实验计划**

为学习助教写任务卡：

1. 选取前三课的正常、依赖和失败案例，为每个案例写输入、预期工具行为及检查证据。
2. 把“帮我学习 Agent”改为一个限定资料范围、输出字段、预算和停止条件的任务。
3. 让另一条失败 trace 按同一判据接受检查，修正含糊标准并保留版本。

产出：一张学习助教任务卡与覆盖正常、失败、缺少证据的最小案例集。

- 放弃条件
- 评估记录

**实验计划**

有上限的目标循环：

1. 定义可检验的目标与放弃条件。
2. 运行目标循环，记录每轮评估。
3. 构造无法完成的目标，确认按条件放弃。

产出：目标循环的逐轮评估记录。

**验收要求**

- 每轮继续或停止都有评估依据。
- 达到预算时停止并如实报告。
