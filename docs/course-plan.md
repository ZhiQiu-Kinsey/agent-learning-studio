## 学习原则

- 本文件是课程分类、课号、先修和规划状态的唯一主数据；网页、API 与课程文档从同一份数据生成。
- 课号以目录登记为准；available 表示平台已有实验，不表示学习者已经掌握。planned 课程仅展示计划，尚不能运行。
- 每课按目标、原理、读代码、预测、实验、trace 对照与自检推进；下列规划实验是后续制作要求，登记课程不等于完成教材和代码。
- 先修按知识依赖设置；RAG 不必先学持久记忆，LangChain 不必先完成 Agentic RAG，独立评估可以在任务验收课后开始。
- 从第 04 课建立最小验收案例，各阶段继续保留成功和边界案例，第 20 课再集中研究独立验证、留出集与回归。
- 采用供应商无关的统一模型接口，百炼作为当前已实测配置；通过成熟 SDK 或适配层支持其他服务，分别保留原始 HTTP 与适配层输入输出。控制变量实验固定当次模型与配置，不限定长期供应商。新增框架按课安装可选依赖，正式实现时核对官方文档并锁定版本。
- 从资料加载课开始说明外部文本不可信，完整权限和提示注入实验在第 23 课完成；程序决定工具执行范围，提示词不能替代权限控制。
- 每个阶段为同一个本地学习助教增加能力，同时保留可独立运行的小实验；阶段成果以引用、参数、状态、实际副作用和终态验收。
- 课程实验以真实模型和真实工具为主；模拟仅供内部自动化测试，不作为学习主线。回放不重新执行工具或模型；模型输出、工具结果、状态更新分别记录，供应商实测、估算和未知指标明确区分，不把动画当作模型内部思考。
- 参考项目提供结构和工程思路，本课程描述与实验原创编写；阅读、源码存在、历史测试和本机复现分别说明，引用固定快照，不宣称整套教程已实现。

## A · 原生基础

从真实 Python 工具调用出发，看懂模型决策、执行结果和失败边界。

### A1 · 工具决策与数据依赖

观察一次调用循环及多个工具之间的实际数据传递。

#### 第 1 课 · 工具选择

**层级：** 必修　**状态：** 已可运行

**先修：** Python 函数、字典、异常与 JSON 基础

观察模型如何从工具定义提出调用，再由 Python 执行并回传结果，形成一次完整回答。

**学习目标**

- 识别工具名称、描述和参数 Schema
- 区分模型提出调用与程序实际执行
- 追踪 tool_call_id 如何连接请求、调用和回执

**知识点与分节**

- 百炼兼容接口与模型请求
- tools 与 JSON Schema
- tool_calls 和 arguments
- Python 工具登记与分派
- tool_call_id 与结果回传
- 真实模型请求与实际工具证据

**实验计划**

加法、时间与独立任务对照：

1. 先预测加法、查时间和两个独立任务各需什么工具，再分别运行现有练习。
2. 展开模型请求与响应，标出工具名称、实际参数、回执和后续请求。
3. 比较三条真实运行 trace，解释工具结果如何进入最终回答，确认回放只移动记录游标。

产出：三条标注后的运行记录与一次调用循环说明。

**验收要求**

- 能从 trace 找到工具定义、模型调用实参和实际工具结果。
- 能用同一个 tool_call_id 对应调用与结果回传，并指出后续模型请求。
- 能解释 Python 执行由程序完成，回放没有再次调用模型或工具。

**参考材料**

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。

#### 第 2 课 · 依赖式多轮调用

**层级：** 必修　**状态：** 已可运行

**先修：** 第 1 课 工具选择

读取本次真实时间，把上一步的 hour 和 minute 作为下一步加法参数，区分依赖与独立任务。

**学习目标**

- 识别工具之间的数据依赖
- 解释消息历史如何携带观察结果
- 验证下一次实参来自本次真实工具输出

**知识点与分节**

- 行动与观察循环
- 依赖图与独立任务
- messages 中的工具结果
- 下一轮参数构造
- 顺序执行与数据传递
- 有来源的答案与偶然猜对

**实验计划**

小时与分钟相加：

1. 预测查时间与加法的先后关系，再运行现有依赖式练习。
2. 在 trace 标出本次 hour/minute 及后续加法参数，核对结果而不使用预先写死的时间。
3. 运行独立任务对照，解释两个任务什么时候可以分别执行。

产出：带数据来源连线的依赖调用记录与独立调用对照。

**验收要求**

- 第二次工具参数与第一次返回的 hour/minute 一致。
- 能指出携带上轮结果的消息，并解释为什么一次模型请求不足以获得未观察的数据。
- 能区分事件按顺序出现和参数确实由上一步数据产生。

**参考材料**

- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/observations.mdx`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`chapter1/context/grounding.py`。

### A2 · 错误与执行边界

通过失败案例确认校验、白名单和停止条件的责任。

#### 第 3 课 · 错误处理与安全边界

**层级：** 必修　**状态：** 已可运行

**先修：** 第 2 课 依赖式多轮调用

通过真实正常除法、零除和越界请求观察模型及工具行为，再以独立程序校验确认未知工具和损坏参数无法绕过边界。

**学习目标**

- 把执行错误作为结构化结果回传
- 确认只执行明确登记的工具
- 区分运行结束、任务成功和预算耗尽

**知识点与分节**

- 参数 JSON 解析与输入校验
- 工具白名单
- 工具异常与 ok=false 回执
- 模型收到错误后的行为
- 轮数预算与停止条件
- 真实模型行为与独立程序校验

**实验计划**

失败安全对照：

1. 通过真实模型运行正常除法与零除，预测并检查各自的工具结果和最终回答。
2. 请求一个未提供的运算或越界操作，观察模型是否调用工具、说明限制或给出无依据回答；未触发的行为如实记录。
3. 阅读并直接验证程序的白名单与参数校验，分别记录未知工具和坏 JSON 的确定性拒绝，与真实模型运行证据区分。

产出：真实模型正常/失败记录、独立程序边界验证及约束责任表。

**验收要求**

- 未知工具未被执行，损坏参数没有绕过解析和校验。
- 零除以错误回执呈现，最终回答没有把失败结果当作有效数字。
- 能指出终止原因，并解释到达轮数上限不能等同任务完成。

**参考材料**

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter4.md`。

## B · 任务与接口

把需求变成可验收任务，用明确的输入、输出和工具契约约束行为。

### B1 · 任务定义与结果契约

定义成功标准，区分结构合法和业务正确。

#### 第 4 课 · 任务目标与验收

**层级：** 必修　**状态：** 已可运行

**先修：** 第 3 课 错误处理与安全边界

在继续写 Agent 前，明确输入范围、输出、约束、证据、失败处理与停止条件，建立最小验收基线。

**学习目标**

- 把模糊需求写成可检查任务卡
- 为正常和边界输入定义成功标准
- 区分生成回答、执行结束与业务完成

**知识点与分节**

- 用户目标与可执行任务
- 输入输出与数据范围
- 成功和失败判据
- 证据要求与未知处理
- 依赖关系与停止条件
- 固定案例与独立检查

**实验计划**

为学习助教写任务卡：

1. 选取前三课的正常、依赖和失败案例，为每个案例写输入、预期工具行为及检查证据。
2. 把“帮我学习 Agent”改为一个限定资料范围、输出字段、预算和停止条件的任务。
3. 让另一条失败 trace 按同一判据接受检查，修正含糊标准并保留版本。

产出：一张学习助教任务卡与覆盖正常、失败、缺少证据的最小案例集。

**验收要求**

- 任务卡包含输入范围、输出要求、证据、失败处理和停止条件。
- 检查项能依据工具结果或产物判断，不能仅靠 Agent 自称完成。
- 至少一个正常案例和一个边界案例能被同一套规则明确判定。

#### 第 5 课 · 结构化输出与业务校验

**层级：** 必修　**状态：** 已可运行

**先修：** 第 4 课 任务目标与验收

使用成熟 Schema 与校验组件接收模型输出，分别检查 JSON 格式、字段约束和业务事实。

**学习目标**

- 设计与任务验收对应的输出 Schema
- 定位格式、Schema 和业务三类错误
- 建立有界修复与明确失败返回

**知识点与分节**

- 统一模型接口与结构化能力差异
- 原始 HTTP 与适配层输入输出
- JSON 格式、字段类型与必填 Schema
- Pydantic 等成熟校验组件
- 业务证据与事实一致性
- 解析失败、有限修复和供应商回退

**实验计划**

学习任务卡结构化提取：

1. 为任务卡定义目标、来源、先修、练习和未知项字段，准备正常、缺字段和越界样例。
2. 通过真实模型提取任务卡后分别执行格式解析、Schema 校验与业务检查，保存各层结果；直接构造的无效数据仅验证校验器。
3. 加入一次有界修复并重新校验，对持续无效结果返回明确失败。

产出：输出 Schema、三层校验结果及有界修复记录。

**验收要求**

- 能分别定位 JSON 损坏、必填字段缺失和事实/业务错误。
- 结构合法但缺少真实来源的内容不会被判为有效任务结果。
- 修复次数受预算约束，最终失败不会被静默改成默认成功数据。

### B2 · 提示词与工具描述

## C · 上下文与状态

管理下一轮模型输入、应用状态及跨会话记忆，保持证据和用户隔离。

### C1 · 消息与应用状态

区分消息历史与程序维护的任务状态。

#### 第 7 课 · 消息与上下文

**层级：** 必修　**状态：** 已可运行

**先修：** 第 2 课 依赖式多轮调用、第 6 课 提示词与工具描述

检查消息角色、历史重发与工具协议，理解模型只能依据本次收到的上下文回答。

**学习目标**

- 按轮构造并解释 messages
- 保持工具调用与结果的合法配对
- 区分协议失败、证据缺失和模型答错

**知识点与分节**

- system、user、assistant 和 tool
- 历史消息与本次请求
- 工具调用结果配对
- 供应商消息协议
- 合法上下文消融
- 当前上下文与持久存储

**实验计划**

连续提问与上下文消融：

1. 运行连续两次提问并展开每轮 messages，标出前一次事实和本次工具观察。
2. 保持协议合法，只删除一组可移除历史或改变事实保留方式，再运行相同问题。
3. 比较 API 状态、证据来源和答案，分别归因拒绝、遗漏与推理错误。

产出：每轮消息图与合法上下文对照记录。

**验收要求**

- 能明确指出后一次请求实际包含哪些历史与工具结果。
- 所有保留的工具调用都有对应回执，实验不会用非法协议冒充能力退化。
- API 拒绝、资料缺失和使用证据错误被分别记录。

#### 第 8 课 · 应用 state 与运行生命周期

**层级：** 必修　**状态：** 已可运行

**先修：** 第 4 课 任务目标与验收、第 7 课 消息与上下文

维护任务目标、证据、步骤和终态，区分程序状态、消息历史与模型输出。

**学习目标**

- 为应用设计明确的状态字段
- 追踪状态由哪些实际事件更新
- 区分等待、结束、失败和任务成功

**知识点与分节**

- messages 与 state 的职责
- 目标、证据和待办字段
- 运行 ID 与会话隔离
- 状态更新与不变量
- 等待、执行和终态
- 完成状态与独立任务结果

**实验计划**

学习任务状态面板：

1. 为一个多步学习任务定义目标、来源、已完成步骤、错误和终止原因字段。
2. 通过实际工具结果更新状态，显示状态更新前后的差异。
3. 触发缺少资料和预算结束，核对终态与任务验收结果是否被分别保存。

产出：状态定义、事件到状态的映射与正常/失败生命周期记录。

**验收要求**

- 状态事实能追溯到实际输入或事件，模型自称完成不能直接改为任务成功。

- 全局、子任务和时间预算
- 取消传播与协作终止

**实验计划**

带证据的课程助教协作：

1. 由协调者分派查资料、生成练习和独立审核，给各角色明确输入、输出、来源与预算。
2. 真实执行并保存交接包，加入一条冲突证据或超长文本，检查摘要和合并是否丢失事实。
3. 设置一个超时子任务，核对取消、预算扣减、未完成说明和最终结果。

产出：委派契约、证据交接包与预算/终态核对表。

**验收要求**

- 每个子任务有独立身份和有限预算，整体不会因递归委派无界增长。
- 最终结论引用真实子任务证据，冲突和截断明确呈现而不被摘要掩盖。
- 超时、取消和未完成子任务影响最终验收，不能把全部子任务返回等同业务成功。

- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter10.md`。

### H3 · 本地交付与毕业项目

#### 第 29 课 · 本地交付、部署与恢复

**层级：** 必修　**状态：** 规划中

**先修：** 第 19 课 人工介入、检查点与恢复、第 21 课 可观测性、usage 与成本、第 22 课 可靠工具、重试与幂等、第 24 课 MCP 原理与工具接入

把开发中的学习工具整理成可启动、可配置、可观测和可恢复的本地应用，验证实际服务可用性。

**学习目标**

- 分离配置、凭据和运行数据
- 建立真实模型及工具可用性检查
- 验证重启恢复、日志定位和升级回退

**知识点与分节**

- 运行环境与依赖锁定
- 供应商配置和凭据管理
- 启动、停止及服务探测
- 数据备份和会话恢复
- 错误日志与敏感数据处理
- 版本升级和回退

**实验计划**

从空环境启动与中断恢复：

1. 在独立本地环境按交付说明安装和启动，选择已验证模型配置，确保凭据不进入源码或 trace。
2. 通过真实模型请求与 MCP 发现/调用检查服务可用性，再在任务暂停处关闭并重启。
3. 核对恢复内容、实际副作用、诊断日志和数据备份，尝试一次可回退配置升级。

产出：本地启动说明、真实可用性报告与恢复/回退记录。

**验收要求**

- 按照说明能从独立环境启动，模型和工具分别接受真实探测。
- 重启后状态和资料按约定恢复，已完成写入不重复，未知供应商没有被标为已验证。
- 配置错误可从界面或日志定位，凭据不泄露，备份和回退有实际检查记录。
