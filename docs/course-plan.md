## A · 原生基础

从一次模型请求出发，到真实的 Python 工具调用，看懂模型决策、执行结果和失败边界。

### A0 · 模型调用基础

一次请求、多轮历史与采样波动：后面每一课都建立在这三件事上。

#### 第 1 课 · 一次模型请求

**课程 ID：** `chat-request`

**层级：** 必修　**状态：** 已可运行　**难度：** 入门　**预计：** 约 20 分钟　**模型：** 调用真实模型

**先修：** Python 函数、字典、异常与 JSON 基础

发出一次不带工具的真实模型请求，读懂请求体里的 model 与 messages、响应里的回答、结束原因和用量。

**本课术语：** Agent、Token、用量（Usage）、消息角色（Message Role）、结束原因（Finish Reason）

**小节**

1. **一次请求就是一个 JSON 对象**：Agent 是由模型决定下一步、由程序去执行的系统。
2. **消息角色：每条消息是谁说的**：messages 里每条消息的 role 就是它的消息角色。
3. **响应：回答和结束原因**：响应也是一个 JSON 对象。
4. **用量：这次花了多少 Token**：Token 是模型切分文本的单位，由分词器决定怎么切，一个汉字不一定正好是一个 Token。
5. **密钥只在后端**：request 事件记录的是请求体，里面没有 API Key。

**学习目标**

- 说出一次模型请求由哪些字段组成
- 从响应中找到回答、结束原因与用量
- 解释系统提示词和输出长度上限如何改变一次回答

**知识点与分节**

- Agent 的每一步都从一次模型请求开始
- 请求体：model 与 messages
- 消息角色：system、user、assistant
- 响应：choices[0].message.content
- 结束原因 finish_reason：stop 与 length
- 用量 usage 与 Token；推理 Token 也算在完成 Token 里
- 密钥只在后端，请求体里没有认证信息

**实验计划**

有没有系统提示词：

1. 先预测这次运行会发出几次模型请求。
2. 运行“带系统提示词”和“去掉系统提示词”，对照两次请求的 messages。
3. 比较两次 response 的 prompt_tokens 和回答，说明哪些差异来自请求本身。

产出：两次真实请求的 messages 与提示 Token 对照。

输出上限与结束原因：

1. 先预测把 max_tokens 设成 16 时，finish_reason 和回答会怎样。
2. 运行“把输出上限设得很小”，展开 response 里的 finish_reason、content 和 usage。
3. 对照 completion_tokens 与 reasoning_tokens，判断截断的是推理还是回答。

产出：一次被截断的真实响应的字段标注。

**验收要求**

- 能指出请求体里的 model、messages 和每条消息的角色。
- 能从响应读出回答、结束原因和服务商报告的用量；没有报告的用量写“未报告”。
- 能解释输出被截断时 finish_reason 为什么是 length，以及 content 为空时怎样从 usage 判断原因。

**参考材料**

- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/messages-and-special-tokens.mdx`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。

#### 第 2 课 · 多轮对话：程序重发历史

**课程 ID：** `multi-turn-history`

**层级：** 必修　**状态：** 已可运行　**难度：** 入门　**预计：** 约 20 分钟　**模型：** 调用真实模型

**先修：** 第 1 课 一次模型请求

连续提问两次，比较带上与不带上一轮消息的请求，看清模型不会自己记住上一轮，多轮对话靠程序重发消息历史。

**本课术语：** 消息历史（Message History）、上下文（Context）

**小节**

1. **模型不会自己记住上一轮**：第 1 课只发了一次请求。
2. **消息历史放在程序这边**：本课的 run 用一个 Python 列表 history 保存消息历史。
3. **上下文：这一次请求里的全部内容**：上下文就是模型在这一次请求里能看到的全部内容。
4. **历史越长，每次请求越大**：带着整段历史，第三轮要发六条消息：system、三条 user、两条 assistant。

**学习目标**

- 解释模型调用之间不保存状态
- 按轮把 assistant 回复放回消息历史
- 从用量看出历史越长、每次请求越大

**知识点与分节**

- 一次调用不保存状态
- 消息历史与 assistant 回复回填
- 带历史与不带历史的对照
- 上下文就是这一次请求里的全部内容
- 提示 Token 随轮次增长

**实验计划**

带历史与不带历史：

1. 先预测“不带历史追问”会发出几次模型请求，模型能否答出第一轮说过的名字。
2. 运行“带历史追问”和“不带历史追问”，对照两组第二轮请求的 messages。
3. 在实验报告里核对第二轮请求有没有第一轮的事实，以及回答有没有用到它。

产出：两种第二轮请求的消息对照。

三轮对话的提示 Token：

1. 运行“三轮对话”，展开第三轮请求的 messages。
2. 在实验报告里记下每轮的 prompt_tokens，算出相邻两轮的差值。

产出：三轮消息数与提示 Token 的变化记录。

**验收要求**

- 能指出第二次请求里哪几条消息来自上一轮。
- 能解释不带历史时模型为什么无法回答。
- 能从用量记录说明历史增长带来的成本。

**参考材料**

- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/messages-and-special-tokens.mdx`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`chapter1/context/agent.py`。

#### 第 3 课 · 采样与不确定性

**课程 ID：** `sampling-variance`

**层级：** 必修　**状态：** 已可运行　**难度：** 入门　**预计：** 约 25 分钟　**模型：** 调用真实模型

**先修：** 第 1 课 一次模型请求

同一提示连续运行多次，比较低温与高温下回答的差异，理解为什么一次运行不能证明结论、实验要重复。

**本课术语：** 对照实验（Controlled Experiment）、采样温度（Temperature）、采样（Sampling）

**小节**

1. **同一个请求，回答可能不同**：本课不调用工具，只做一件事：把同一个请求原样发 5 次，数一数回答有几种。
2. **采样温度：只改抽法**：请求里的 temperature 就是采样温度。
3. **温度为 0 也不保证一样**：temperature 为 0 时，每一步都该取概率最高的候选，回答应该很稳定。
4. **一次运行能证明什么**：第 1 课比较过有没有系统提示词。

**学习目标**

- 解释模型输出来自采样
- 比较采样温度对回答波动的影响
- 说明对照实验为什么要固定条件并重复运行

**知识点与分节**

- 采样与概率分布
- 采样温度 temperature 只改抽法，不改信息
- 温度为 0 也不保证完全相同
- 重复运行与不同回答数
- 对照实验：只改一个条件，每组重复
- 一次运行能证明什么、不能证明什么

**实验计划**

低温与高温各运行 5 次：

1. 先预测一次运行会发出几次模型请求，温度为 0 与 1.3 时 5 次回答会有几种。
2. 分别运行“temperature 设为 0”和“temperature 设为 1.3”，每次连续发出 5 个相同请求。
3. 比较两组的不同回答数和每次的完成 Token，说明后面的对照实验为什么要多跑几次。

产出：两组各 5 次真实回答的对照表。

**验收要求**

- 每个回答都来自真实响应，不同回答数由程序统计。
- 能说明温度只改变采样方式，不改变请求里的信息。
- 能指出一次运行的差异可能只是波动。

**参考材料**

- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。
- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/what-are-llms.mdx`。

#### 第 4 课 · 工具定义与调用提议

**课程 ID：** `tool-proposals`

**层级：** 必修　**状态：** 已可运行　**难度：** 入门　**预计：** 约 30 分钟　**模型：** 调用真实模型

**先修：** 第 1 课 一次模型请求

把工具定义随请求发给模型，只看模型提出的调用：选哪个工具、参数是什么，本课不执行任何工具。

**本课术语：** 工具调用（Tool Calling）、JSON Schema、工具描述（Tool Description）

**小节**

1. **请求里多了 tools**：第 1 课的请求只有 messages。
2. **JSON Schema 描述参数**：每条工具定义的 parameters 是一段 JSON Schema。
3. **调用提议：tool_calls 里写了什么**：模型决定用工具时，响应的 message 里会有 tool_calls 列表，content 往往是空的，也可能带一句说明。
4. **提议不等于执行**：tool_calls 只是模型写下的调用提议，像一张填好的申请单。
5. **用不着工具时，直接回答**：闲聊问题用不着加法，也用不着时间。

**学习目标**

- 读懂工具定义里的名称、描述和参数 JSON Schema
- 从响应找到 tool_calls 与 JSON 字符串形式的参数
- 区分“模型提出调用”和“程序执行工具”

**知识点与分节**

- tools 与 tool_choice
- 工具描述决定何时被选中
- 参数的 JSON Schema
- tool_calls 与 JSON 字符串形式的 arguments
- finish_reason 为 tool_calls
- 不需要工具时直接回答
- 调用提议不等于执行

**实验计划**

加法、查时间与闲聊：

1. 先预测“问加法”会出现几个 tool_result 事件，三个问题各会不会提出调用、提出哪个工具。
2. 分别运行三个练习，展开响应里的 tool_calls、arguments 和 finish_reason。
3. 确认三次运行的事件里都没有 tool_call 和 tool_result：本课只观察提议。

产出：三条真实响应的调用提议标注。

**验收要求**

- 能从响应找到工具名和 JSON 字符串参数。
- 能解释闲聊问题为什么没有调用提议。
- 能指出本课运行里没有任何工具被执行。

**参考材料**

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。
- [Hugging Face Agents Course](https://github.com/huggingface/agents-course)：`units/en/unit1/tools.mdx`。

#### 第 5 课 · 执行工具与回传结果

**课程 ID：** `tool-selection`

**层级：** 必修　**状态：** 已可运行　**难度：** 入门　**预计：** 约 30 分钟　**模型：** 调用真实模型

**先修：** 第 4 课 工具定义与调用提议、第 2 课 多轮对话：程序重发历史

让 Python 按白名单执行模型提出的调用，把工具结果用同一个调用 id 写回消息历史，再请求一次模型，形成最小 Agent 循环。

**本课术语：** 运行层（Harness）、工具结果（Tool Result）、Agent 循环（Agent Loop）、白名单（Allowlist）

**小节**

1. **从调用提议到执行**：第 4 课停在调用提议：模型在 tool_calls 里写下工具名和 JSON 字符串参数，没有任何东西被执行。
2. **工具结果用 tool 消息送回**：函数返回后，execute_tool 把结果包成 {"ok": true, "result": 42}；出错时 ok 为 false，带 error_type…
3. **第二次请求：模型第一次看到结果**：工具执行完，run_agent 回到循环开头，把完整的 messages 再发一次。
4. **最小 Agent 循环：四步与轮数上限**：run_agent 只有四步：1. 用系统提示词和问题建立消息历史；2. 带着消息历史和 tools 请求模型；3. 响应里没有 tool_calls，就把 …
5. **运行层与回放**：模型只负责提出调用和写回答。

**学习目标**

- 说明运行器如何按名字分派到登记的函数
- 用 tool_call_id 把调用和工具结果配对
- 追踪工具结果如何进入下一次请求并成为回答依据

**知识点与分节**

- 登记的工具与分派
- role=tool 消息与 tool_call_id
- 第二次请求里的工具结果
- 最小 Agent 循环的四步
- 轮数上限
- 回放只读取已有记录

**实验计划**

加法与查时间：完整的一次循环：

1. 先预测一次加法会发出几次模型请求、产生几个工具结果。
2. 运行“计算加法”和“查询本地时间”，按顺序标出调用提议、tool_call、tool_result 和第二次请求。
3. 在第二次请求的 messages 里找到 role 为 tool 的消息，说明回答的依据。

产出：一次完整循环的事件标注与调用 id 连线。

**验收要求**

- 能用同一个 tool_call_id 对应调用与工具结果。
- 能指出第二次请求比第一次多了哪两条消息。
- 能解释工具由 Python 执行，回放没有再次调用模型或工具。

- [Microsoft AI Agents for Beginners](https://github.com/microsoft/ai-agents-for-beginners)：`04-tool-use/README.md`。
- [深入理解 AI Agent：设计原理与工程实践](https://github.com/bojieli/ai-agent-book)：`book/chapter1.md`。

#### 第 6 课 · 依赖式多轮调用

**课程 ID：** `dependent-calls`

**层级：** 必修　**状态：** 已可运行　**难度：** 入门　**预计：** 约 30 分钟　**模型：** 调用真实模型

**先修：** 第 5 课 执行工具与回传结果

读取本次真实时间，把上一步的 hour 和 minute 作为下一步加法参数；再对照同一轮提出、逐个执行的两个独立调用。

**本课术语：** 轨迹（Trace）

**小节**

1. **先看数据依赖，再安排步骤**：“把现在的小时和分钟相加”看起来只有一句话，却需要两个能力：读取时间和计算加法。

**知识点与分节**

- 依赖图与独立任务
- messages 中的工具结果

- 沿轨迹核对参数来源
- 有来源的答案与偶然猜对
- 同一轮提出多个调用，运行器逐个执行

**实验计划**

上一步的结果，决定下一步的参数：

1. 先预测“小时与分钟相加”会发出几次模型请求。
2. 在轨迹里标出本次 hour、minute 及后续加法参数，核对结果而不使用预先写死的时间。

产出：带数据来源连线的依赖调用记录。

两个独立任务：同一轮提出，逐个执行：

1. 运行“两个独立任务”，查看第一轮响应里是否有两个调用提议。

**本课术语：** 消息协议（Message Protocol）

**小节**

5. **怎么读这次运行**：分三层看，一层一层排除。
6. **局限与成本**：一次运行发四次请求，每次都带着几乎相同的消息，开销是只发一次的好几倍。

**学习目标**

- 说出一次请求的上下文由哪几部分组成、各自提供什么

- 合法消融：一次只拿掉一部分，其余一字不改
- 消息协议：调用与结果靠调用 id 配对
- 发送前的协议检查 validate_tool_history
- 关键词初筛与阅读回答原文

1. 先预测：五组上下文里有一组只拿掉工具结果，这次运行会发出几次模型调用。
2. 运行“四部分逐一拿掉”，对照每组 request 的 messages 与回答，标出分数、复习日和“依据：”行分别来自哪一部分。

**先修：** 第 8 课 任务目标与验收、第 11 课 上下文组成与消息协议

本课不调用模型。用一个类型化状态机维护任务目标、证据、步骤和终态，区分程序状态、消息历史与模型输出。

**本课术语：** 应用状态（Application State）

**小节**

1. **消息和状态各管什么**：本课不调用模型。
2. **一份状态长什么样**：TaskState 有八个字段。
3. **步骤预算与状态快照**：本课一次运行最多三步：读取本地资料索引、核对资料来源、生成课内资料要点。
4. **转换规则守住边界**：status 只能沿转换表 TRANSITIONS 走：ready 只能进入 running 或 cancelled；running 可以进入 waiting…
5. **等待、失败和预算结束**：缺少资料时先进入 waiting，随后以“本次预设没有可核验的资料，无法完成目标。
6. **会话隔离与取消**：每次运行都新建 TaskState 和 run_id，不用全局的可变状态，两次运行的状态不会互相覆盖。

**学习目标**

- 说出应用状态的各个字段记录什么，并与消息历史分开保存
- 顺着状态快照追踪每次状态变化由哪一步引起
- 区分等待、完成和失败（资料缺失或预算耗尽），并为终态写明原因

**知识点与分节**

- messages 与应用状态各管什么
- TaskState：目标、证据、步骤、产物和终态原因
- 步骤预算：每步执行前扣减
- 转换表与状态机：非法转换直接拒绝

- 运行 ID、会话隔离与取消

**实验计划**

三种终态，各有原因：

1. 先预测“资料存在，步骤预算 3”这次运行会发布几份状态快照。
2. 依次运行有证据完成、资料缺失、预算耗尽三组预设，顺着 lesson.state 写出每组的状态转换顺序。
3. 对照报告里的终态原因、证据数、已执行步骤与消息数；再把步骤预算改成 1 运行一次，比较结局。

产出：各组运行的状态转换顺序与终态原因记录。

**验收要求**

- 每次状态变化都能追溯到 lesson.state 快照；只有证据和产物都在时才能进入 completed，模型文字无法直接改写状态。

#### 第 13 课 · 上下文预算与截取窗口

**课程 ID：** `context-budget`

**层级：** 必修　**状态：** 已可运行　**难度：** 进阶　**预计：** 约 40 分钟　**模型：** 调用真实模型

**本课术语：** 上下文窗口（Context Window）、上下文预算（Context Budget）

**小节**

1. **一次请求能装多少**：模型一次请求能处理的长度有上限，这个上限叫上下文窗口（Context Window），输入的消息和模型的输出共用它。
2. **字符数、Token 和用量**：char_budget 量的是把 messages 序列化成紧凑 JSON 之后的字符数。
3. **完整历史的代价**：完整历史把所有消息原样带上：目标、那次工具调用和工具结果、旁支讨论和最后的追问。
4. **截取窗口：从最新的消息往回装**：截取窗口先留下 system 和当前问题，再从最新的消息往回，一组一组地装，下一组装不下就停。
5. **按条数截断会拆开配对**：另一种常见写法是“只保留最后 N 条消息”。
6. **实验报告怎么读**：实验报告把两种布局并排：消息数、JSON 字符数、是否在预算内、有没有来源和事实，都从实际发出的请求逐条检查；服务商用量只在响应里真的有时才显示。

**学习目标**

- 解释上下文窗口与上下文预算，分清本地字符数、Token 与服务商用量
- 实现按预算截取、工具调用与工具结果整组进出的截取窗口
- 说明按条数截断拆开工具配对会发生什么

**知识点与分节**

- 上下文窗口与上下文预算
- 本地字符数、Token 与服务商用量
- 旁支历史让完整历史变长
- 截取窗口：从最新往回装，工具交互整组进出
- 按条数截断拆开工具配对
- 服务商对孤立工具结果的真实回应

**实验计划**

完整历史与截取窗口：

1. 预测这次运行有几个 tool_call 事件，以及截取窗口会舍弃哪些消息。
2. 分别用 600 和 4000 字符的预算运行，比较两种布局的消息数、字符数、来源和回答。
3. 在窗口事件里核对保留与舍弃的消息数，以及工具结果还在不在。

产出：两种预算下的布局对照与来源检查。

1. 把旁支讨论从 8 轮调到 20 轮，其余不变。
2. 比较完整历史与截取窗口的字符数变化。

产出：旁支增长前后的长度对照。

拆开工具调用与工具结果：

1. 运行拆开配对练习，记录本地协议检查的结论。
2. 用真实模型查看服务商对孤立工具结果的回应。

产出：两种截断的协议检查与服务商回应记录。

**验收要求**

#### 第 14 课 · 上下文压缩与探针问题

**课程 ID：** `context-compaction`

**层级：** 必修　**状态：** 已可运行　**难度：** 进阶　**预计：** 约 45 分钟　**模型：** 调用真实模型

**先修：** 第 13 课 上下文预算与截取窗口

比较规则压缩、清理旧工具结果和模型摘要三种压缩方式，用只有最早那次工具结果才能回答的探针问题，检查信息是否还在。

**本课术语：** 上下文压缩（Context Compression）

**小节**

1. **截掉之外的另一条路**：第 13 课的截取窗口只做一件事：装不下的旧消息整组舍弃。
2. **探针问题：只有旧信息才能答**：压缩之后信息丢没丢，看长度看不出来。
3. **规则压缩：程序决定留什么**：规则压缩由程序按固定字段拼一条记录：目标、约束、来源、事实、待办，不调用模型。
4. **清理旧工具结果：位置还在，内容没了**：长任务里，早先的工具结果往往占掉大半长度。
5. **摘要压缩：模型决定留什么**：摘要压缩多发一次请求：把较早部分原样交给模型，再附一条压缩指令，让它写一段摘要；之后的请求用这段摘要代替较早部分。
6. **实验报告怎么读**：实验报告的表格每组一行：消息数、JSON 字符数、原话还在上下文里、探针回答、初筛结果和服务商用量。

**学习目标**

- 区分规则压缩、清理旧工具结果与模型摘要

- 说明每种压缩的成本与风险

**知识点与分节**

- 上下文压缩只改写较早部分
- 规则压缩：目标、约束、来源、事实、待办；装不下就报错
- 清理旧工具结果：保留位置，替换内容
- 模型摘要多一次请求，指令影响留下什么
- 探针问题
- 压缩前后的字符数与用量

**实验计划**

三种压缩，同一个探针问题：

1. 预测这次运行有几个 request 事件。
2. 运行压缩对照练习，查看每组压缩后的上下文与探针回答。
3. 比较原话是否还在上下文里，以及回答是否答出来源与原话。

产出：四组上下文、探针回答与损失记录。

规则压缩的预算装不下证据：

1. 把规则压缩的字符预算从 300 降到 100，其余不变。
2. 查看拒绝原因，对比两次运行的模型调用数。

产出：拒绝事件与模型调用数对照。

摘要指令决定留下什么：

1. 换成只要求一两句话的摘要指令，其余不变。
2. 对比两次的摘要原文与摘要压缩那组的探针结果。

产出：两条指令下的摘要与探针对照。

**验收要求**

- 每种压缩后的上下文都通过协议检查。
- 探针结论分开记录本地字符串检查与关键词初筛。

### C4 · 缓存与技能

稳定前缀如何复用，技能说明如何按需进入上下文。

#### 第 17 课 · 提示缓存与稳定前缀

**课程 ID：** `prompt-caching`

**层级：** 必修　**状态：** 已可运行　**难度：** 进阶　**预计：** 约 45 分钟　**模型：** 调用真实模型

**先修：** 第 13 课 上下文预算与截取窗口

同一份长资料连续发几次请求，比较动态内容在前、稳定前缀与预热三种结构，用服务商实际报告的缓存字段和本地前缀哈希判断开头能否复用。

**本课术语：** 提示缓存（Prompt Caching）、稳定前缀（Stable Prefix）、缓存命中 Token（Cached Tokens）

**小节**

1. **开头每轮都一样，却每轮都重新处理**：第 13 课里我们看到，每次请求都要把整段上下文重新发给模型。
2. **只认从第一个字开始的相同**：缓存按前缀匹配：拿这次请求和之前的请求从第一个字开始比，一直比到第一个不同的字为止，只有这之前的部分可能被复用。
3. **从用量里读出命中多少**：命中了多少，只能看服务商在响应的用量里怎么报告。
4. **没有报告，就写未报告**：有的服务商或接口不返回缓存字段。
5. **前缀哈希：先在本地确认开头没变**：命中数由服务商给出，会因为缓存过期、服务器调度等原因波动。
6. **预热：把第一次的冷请求挪到前面**：稳定前缀组的第 1 次请求，服务商还没见过这段前缀，通常不会命中，之后的请求才可能命中。
7. **Agent 里最容易破坏前缀的写法**：真实的 Agent 每轮请求，开头通常是系统提示词和工具定义，后面接越来越长的消息历史。
8. **一次运行能说明什么**：命中与否由服务商决定。

**学习目标**

- 说明提示缓存只复用逐字相同的前缀，动态内容的位置决定开头能否复用
- 从用量读取各服务商的缓存字段，归一化为缓存命中 Token 与命中比例
- 区分“服务商报告为 0”与“未报告”，用前缀哈希在本地核对前缀是否相同

**知识点与分节**

2. **工人的输入要小**：每个工人只拿到编排者给它的那一句指令，加上对应那一课的要点，看不到其他工人在做什么。
3. **一个写，一个评，有上限地轮流**：评估者-优化者（Evaluator-Optimizer）是另一种两角色模式：生成者（模式名里的“优化者”）写一版，评估者按量规检查，给出 pass 或 rev…
4. **调用账本：多花的钱换来了什么**：运行器为每次调用记一行账：角色（单次调用、编排者、工人、生成者、评估者）、轮次、branch，以及服务商在响应里报告的 total_tokens。

**学习目标**

- 说明编排的 N+1 次调用成本
- 为评估者-优化者设置 max_iters
- 在时间线上分开追踪并行的工人请求

**知识点与分节**

- 计划产物
- 带分支的并行工人请求
- 评审结论
- 迭代上限
- 成本统计

**实验计划**

编排与评审修订：

1. 编排者生成计划，工人在同一轮里各发一个带 branch 的并行请求。
2. 评估者评审、生成者修订，在迭代上限 max_iters 内反复，记录每轮评审结论。
3. 统计相对单次调用的额外成本。

产出：带分支的请求时间线、评审记录与成本对比。

**验收要求**

- 每个工人的请求在时间线上按分支分开显示。
- 评审修订一定在迭代上限内停止。
- 成本来自实际用量。

#### 第 25 课 · 资料加载与分块

**课程 ID：** `document-loading`

**层级：** 必修　**状态：** 规划中　**难度：** 进阶　**预计：** 约 45 分钟　**模型：** 调用真实模型

**小节**

1. **为什么要先加载和分块**：模型一次读不下整本资料，检索要以小片段为单位，片段还得能指回原文。
2. **加载与清洗**：把 Markdown、文本等本地资料读成纯文本，记录来源路径、标题与版本。
3. **分块大小与重叠**：同一份资料按不同大小和重叠切块，比较片段数与跨块断句。
4. **片段 ID 与原文定位**：每个片段带稳定 ID 和行号范围，后面的引用才能核对。
5. **外部文本不可信**：资料里的“指令”只是数据；从加载这一步就标出信任等级。
6. **失败情况**：空文档、重复内容、解析失败分别记录，不悄悄跳过。

**学习目标**

- 保留文档来源、版本与片段定位
- 用实际查询比较分块和重叠的取舍

**知识点与分节**

- 文档加载与格式清洗
- 来源路径、标题和版本
- 分块大小、重叠和上下文
- 片段 ID 与原文定位
- 外部文本不可信
- 空文档、重复内容和解析失败

3. 加入空文档、重复段落和伪装为指令的资料文本，检查加载记录与信任标记。

产出：固定语料清单、两份片段目录及加载异常记录。

**验收要求**

- 每个片段能定位回实际文档与位置，清洗没有丢失关键来源。

#### 第 27 课 · Embedding 与向量检索

#### 第 28 课 · 混合检索与重排

**课程 ID：** `hybrid-retrieval`

**层级：** 必修　**状态：** 规划中　**难度：** 进阶　**预计：** 约 45 分钟　**模型：** 调用真实模型

**先修：** 第 27 课 Embedding 与向量检索

把关键词与向量检索的结果合并、重排，在同一查询集上比较三种检索，并处理索引更新与删除。

**本课术语：** 向量检索（Vector Retrieval）、混合检索（Hybrid Retrieval）

**小节**

1. **为什么要混合**：关键词与向量各有漏检，合并两份结果往往更稳。
2. **结果合并（RRF）**：按排名而不是分数合并，避免两种分数尺度不同。
3. **重排**：用更贵的模型给少量候选重新排序，比较重排前后的命中。
4. **元数据过滤与 top-k**：按来源、时间过滤，再取前 k 条，记录过滤掉了什么。
5. **索引更新与删除**：资料改了或删了，旧片段不能继续被检索到。

**学习目标**

- 建立可检查的关键词与向量检索
- 用固定查询比较各策略召回和排序
- 维护索引、元数据过滤和知识更新

**知识点与分节**

- 结果合并（RRF）
- 重排
- 元数据过滤与 top-k
- 索引版本、更新和删除
- 三种检索的同一查询集对照

**实验计划**

同一题集比较三种检索：

1. 为固定资料写名称精确查询、同义表达、无答案和跨段查询，并标注应命中的片段。
2. 分别运行关键词、向量与混合策略，显示每次实际命中、分数和来源，不直接比较不可通用的分数尺度。
3. 修改或删除一份资料并更新索引，核对过滤、重启恢复和旧片段失效。

产出：三种检索的命中对照表与索引更新验证记录。

**验收要求**

- 每种策略的检索结果可独立查看，命中与生成答案没有混为一项评分。
- 比较使用相同语料和查询，能说明至少一个策略优势及失败例。
- 更新或删除后旧片段不再作为当前证据，索引版本和来源一致。

#### 第 29 课 · RAG 回答与引用

**课程 ID：** `rag-citations`

**层级：** 必修　**状态：** 规划中　**难度：** 进阶　**预计：** 约 45 分钟　**模型：** 调用真实模型

把实际检索片段提供给模型，生成可追溯回答，并处理资料不足和互相冲突的来源。

**本课术语：** 检索增强生成（Retrieval-Augmented Generation）、来源引用（Citation）

**小节**

1. **把检索结果交给模型**：检索片段放进请求，和问题分开标注，模型才能区分资料与指令。
2. **引用格式**：回答里写片段 ID，程序检查引用是否存在。
3. **引用是否真的支持结论**：存在不等于支持：逐条核对引用片段里有没有回答所说的内容。
4. **资料不足时**：检索不到依据就明说不知道，而不是让模型补全。
5. **资料冲突与时效**：两条片段说法不同，回答要列出分歧和各自的来源。
6. **检索质量与生成质量分开看**：答错时先查检索有没有找到依据，再查模型有没有用对。

**学习目标**

- 构造检索到回答的证据链
- 校验引用实际存在且支持结论
- 区分检索失败和证据使用错误

**知识点与分节**

- 检索上下文与生成提示
- 片段 ID、来源和引用格式
- 引用存在性与支持关系
- 无答案与不确定性
- 资料冲突与时效
- 检索质量和生成质量分层

**实验计划**

有证据、无证据和冲突资料问答：

1. 准备可回答、资料中不存在及两个版本冲突的固定问题，标出各自证据范围。
2. 运行检索与回答，保存实际送入模型的片段和每个回答引用。
3. 逐条核对引用是否存在并支持结论，对缺少或冲突资料检查说明。

产出：问答记录、引用校验表和检索/生成失败分类。

**验收要求**

- 每条引用能回到本次实际检索片段，不能指向未提供的虚构来源。
- 资料不足时明确说明，冲突资料分别列出来源与限制。
- 检索未命中和命中后误用被分开定位，答案流畅不能代替证据充分。

#### 第 30 课 · Agentic RAG 与有上限的迭代

**课程 ID：** `agentic-rag`

- 检索工具与查询路由
- 查询改写和子问题
- 观察反馈与证据覆盖
- 重复查询和尝试记录
- 调用、轮数及时间预算
- 静态 RAG 与 Agentic RAG 对照

**验收要求**

- 每次检索均有实际查询和返回证据，下一次行动可对应已有观察。
- 重复搜索或无答案任务能在预算内结束，并说明未完成原因。

1. **为什么不用 bash 改文件**：专门的读写工具能校验路径、记录前后内容，出错更容易定位。
2. **整文件写入与局部替换**：比较两种编辑方式在大文件上的成功率与风险。
3. **前后哈希与 diff**：用哈希证明文件确实变了，用 diff 说明改了什么。
4. **冲突与过期检测**：文件在读取后被改过，编辑要拒绝而不是覆盖。

**学习目标**

- 设计安全的文件读写与编辑工具
- 比较整文件重写与局部替换
- 用哈希与 diff 留下变更证据

**知识点与分节**

- 路径校验
- 整文件写入与局部替换
- 前后哈希
- 统一 diff
- 冲突与过期检测

**实验计划**

两种编辑策略的对照：

1. 同一修改任务分别用整文件重写和局部替换完成。
2. 记录每次修改的前后哈希与统一 diff。
3. 模拟文件在读取后被外部修改，检查工具能否发现过期。

产出：两种策略的 diff 记录与过期检测结果。

**验收要求**

- 所有路径都被解析并限制在工作区内。
- 每次修改都有前后哈希与 diff。
- 过期写入被拒绝而不是覆盖。

#### 第 48 课 · 委派、上下文合并与预算

**课程 ID：** `delegation-budget`

**层级：** 进阶　**状态：** 规划中　**难度：** 挑战　**预计：** 约 60 分钟　**模型：** 调用真实模型

**先修：** 第 35 课 并行、超时与并发上限、第 41 课 可观测性、usage 与成本、第 47 课 多 Agent 模式与取舍

为子任务规定输入、输出、证据和停止条件，隔离上下文并验证合并结果及共享预算。

**小节**

1. **子任务契约**：交出去的任务写清输入、输出、证据和停止条件。
2. **结果合并与冲突**：多个子任务的结果合并时，冲突要列出来而不是随便选一个。
3. **共享预算**：全局预算分给子任务，任何一个超支都要能停下。

**学习目标**

- 设计可验收的委派契约
- 保留交接证据并避免污染上下文

**知识点与分节**

- 子任务契约与角色能力
- 共享与隔离上下文
- 证据包和来源元数据

- 取消传播与协作终止

**实验计划**

带证据的课程助教协作：

1. 由协调者分派查资料、生成练习和独立审核，给各角色明确输入、输出、来源与预算。
2. 真实执行并保存交接包，加入一条冲突证据或超长文本，检查摘要和合并是否丢失事实。
3. 设置一个超时子任务，核对取消、预算扣减、未完成说明和最终结果。

产出：委派契约、证据交接包与预算/终态核对表。

**验收要求**

- 每个子任务有独立身份和有限预算，整体不会因递归委派无界增长。

#### 第 49 课 · 后台与定时任务

#### 第 50 课 · 目标循环与放弃条件

**课程 ID：** `goal-loops`

**层级：** 必修　**状态：** 规划中　**难度：** 挑战　**预计：** 约 60 分钟　**模型：** 调用真实模型

**先修：** 第 49 课 后台与定时任务

**小节**

1. **目标要能检验**：把目标写成程序能判断的条件，而不是“做好为止”。
2. **独立的目标评估**：执行者说完成不算，评估者按条件判断继续、完成或放弃。
3. **预算与放弃条件**：轮数、时间和费用都有上限，到了就如实放弃。
4. **逐轮记录**：每一轮的评估依据都留下来，回放时能看到为什么继续或停止。

**学习目标**

- 实现独立于执行者的目标评估
- 设置预算与放弃条件

**知识点与分节**

- 目标评估
- 继续、完成与放弃
- 预算与超时
- 放弃条件
- 评估记录

**实验计划**

有上限的目标循环：

1. 定义可检验的目标与放弃条件。
2. 运行目标循环，记录每轮评估。
3. 构造无法完成的目标，确认按条件放弃。

产出：目标循环的逐轮评估记录。

**验收要求**

- 每轮继续或停止都有评估依据。
- 达到预算时停止并如实报告。
- 执行者的“已完成”不替代评估结论。

完成工具边界、框架对照和权限课后再学。用同一任务比较生成代码与 JSON 工具调用，执行生成代码需要另行设计隔离与预算。

### X2 · LlamaIndex：检索组件与工作流

完成 RAG 引用回答后再学。保持固定语料、查询集和引用标准，比较组件与索引组织，不另起一套无法对照的案例。

先修：第 28 课、第 29 课

- 文档、节点与元数据
- 加载、索引、存储、查询、评估
- QueryEngine 作为 Agent 工具
- 检索和生成质量的配对比较

### X3 · Microsoft Agent Framework 与 Foundry

理解原生循环和 LangChain 适配后按需要选学。使用独立环境与账户配置，比较会话、工具和编排抽象，云端部署另计成本与权限。

先修：第 31 课、第 32 课、第 41 课

- 模型服务商与客户端适配
- 会话与工具抽象
- 工作流和服务端责任
- Foundry 接入及观测对照

### X4 · 浏览器与多模态 Agent

完成人工介入、独立评估与权限课后再学。先选固定网页或图片任务，定义动作与证据，加入误识别、页面变化和确认案例。

先修：第 37 课、第 40 课、第 43 课

- 图像与界面证据
- 浏览器动作和运行反馈
- 人工确认与执行范围
- 误识别、页面变化与可重复评估

### X5 · 本地模型与离线运行

模型请求、RAG 与用量课掌握后按机器条件选学。实际核对硬件、模型许可证和能力，再在同一题集比较百炼与本地模型。

先修：第 28 课、第 31 课、第 41 课

- 本地兼容接口与模型加载
- 硬件、量化与延迟

### X6 · 工具调用微调与强化学习

完成独立评估与毕业项目后，补齐机器学习、数据和训练基础再学。先证明错误来自模型能力，并与提示词、工具设计或检索改进比较。

先修：第 40 课、第 43 课、第 53 课

- 训练数据和留出评估
- Function calling 监督微调
- 任务奖励与强化学习基础
- 训练成本、能力退化和版本回退
